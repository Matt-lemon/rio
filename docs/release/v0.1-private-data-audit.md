# v0.1 private-data audit — interim

2026-10-21. 원본 repository와 운영 상태는 보존했다. 이 문서에는 token 원문, 내부 주소, 사용자 절대 경로, 실제 기기 식별자를 적지 않는다.

## 실행 범위와 결과

- 원본 모든 refs의 private Git bundle을 생성하고 0600으로 보관했다. raw bundle은 public 배포 대상이 아니다.
- Gitleaks 8.30.1 배포물은 게시자 checksum과 대조한 뒤 사용했다. `git --all --full-history`, redaction, inline allow 주석 무시로 검사했다. 도구가 처리한 297개 diff commit에서 rule finding은 0개였다. 이것이 모든 종류의 secret 부재를 증명하지 않는다.
- 별도 전체 blob 검사는 1,349개 reachable blob 버전을 조사했다. 실제 사용자 경로가 포함된 버전 225개, 내부 주소 75개, UUID 형태 식별자 25개가 발견돼 이력 정제 대상으로 표시했다. 일부는 합성 fixture일 수 있어 원문 없는 유형별 보고와 개별 비공개 검토를 구분했다.
- 20개 worktree의 tracked/untracked/ignored inventory를 만들었다. 중복 내용은 합쳐 888개 text blob을 추가 검사했다. 큰 binary는 secret text scanner로 검사 완료라 주장하지 않고 export 금지 대상으로 분류했다.
- 작업 영역 검사 269개 finding 중 257개는 비공개 log/state, 4개는 credential/config, 8개는 예제/실험 manifest 재검토 대상으로 분류됐다. 실제 credential 형식은 ignored `.env`에 있었으며 원문은 출력하지 않았다. 이번 Git-history 검사에는 검출되지 않았다. 모든 finding을 가짜라고 간주하거나 자동 allowlist하지 않았다.
- 운영 `.env`, DB, 로그, 캐시, 모델, 음성 파일을 삭제하거나 바꾸지 않았다. remove는 public export 제외를 뜻한다.

## 아직 완료되지 않은 항목

현재 branch는 감사 작업 영역이며 원본 main 이력이 그대로 연결돼 있다. 그대로 public으로 바꾸거나 `push --mirror`해서는 안 된다. 공개 전에는 별도 local mirror에서 allowlist/path filtering 및 알려진 deployment literal 정제를 수행하고, 날짜/commit mapping과 원본 private bundle을 보존해야 한다.

그 사본의 모든 이력과 새 working tree에 secret/privacy/license 검사를 다시 실행해야 한다. 현재 0개라는 Git secret 결과를 정제된 최종 사본의 성공 결과로 재사용하지 않는다. Runtime 구조와 권한을 바꾸지 않고 정제할 수 없는 내용은 공개 범위에서 제외한다.
