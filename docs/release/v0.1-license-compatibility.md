# Rio v0.1 — GPL-3.0 / Apache-2.0 compatibility audit

확인일: 2026-10-21. 판정: **두 안 모두 검토한 Core 소스 범위에서는 조건부 가능. 감사 후 사용자가 **GPL-3.0-only**를 선택했다. [최종 선택 기록](license-decision.md)을 적용하며 외부 공개 승인은 별도다.**

## 기준과 범위

원격 main은 `160657ffaf95374cb3a3f1ef191ce3f0db34e66e`다. Execution Core와 최신 CI는 이 main에 없으므로 기존 통합 후보 `2542abe9a50c13df94409c6a4cb8f3fcf5ac2841`를 별도 비교 대상으로 조사했다. 운영 Core는 `25101efbe4f09adef9fd3010cb2b5422c867b2ab`이며 이번 감사로 변경하지 않았다. 공개 후보 작업 영역은 원격 main에서 분리했다. 원격 main과 기존 통합 후보의 이력을 보존하면서, Core 및 관련 인터페이스·기존 검사를 선별했다. 새 실행 기능은 추가하지 않았다.

소스 전용 architecture preview를 전제로 한다. 모델, 음성/캐릭터 asset, 인증, 운영 DB, wheel/실행파일/컨테이너 이미지의 재배포 승인은 포함하지 않는다. 개발 도구나 외부 프로그램을 사용했다는 이유만으로 그 프로그램의 라이선스를 Rio 소스의 라이선스로 간주하지 않는다.

## 두 안 비교

| 항목 | GPL-3.0 안 | Apache-2.0 안 |
| --- | --- | --- |
| 현재 Core 의존성의 MIT/BSD/Apache/PSF 등 | 고지와 원래 조건을 유지하는 조합 가능 | 고지와 원래 조건을 유지하는 조합 가능 |
| Chat On Steroids 고정 커밋(MIT) | 참조 표기 유지; 실제 코드 사용 시 MIT 고지 보존 | 같은 조건 |
| certifi(MPL-2.0) | MPL 파일 의무 유지. GPL 복합물로 추가 배포한다면 MPL 3.3 및 secondary-license 제한 확인 | MPL 파일 의무 유지. Rio 전체를 MPL로 바꾸는 것으로 해석하지 않음 |
| 향후 GPLv3 코드를 실제 결합/이식 | GPL 호환 조건으로 검토 가능 | 결합물을 Apache-only라고 배포할 수 없음; 격리/제외/별도 허가 검토 |
| Rio 수정본을 배포하는 downstream | GPL 적용 범위에 대한 같은 라이선스·Corresponding Source 등 의무 | GPL과 같은 포괄적 소스 공개 조건은 없지만 라이선스·고지·변경 표기 조건은 유지 |
| 모델/음성/캐릭터/외부 바이너리 | 별도 권리. GPL을 붙여 해결되지 않음 | 별도 권리. Apache를 붙여 해결되지 않음 |
| 원본 기여자의 권리·출처가 불명확한 파일 | 격리 필요 | 격리 필요 |

Apache-2.0 코드를 GPLv3 프로젝트에 포함하는 방향과 그 반대 방향은 대칭이 아니다. [ASF의 공식 호환성 설명](https://www.apache.org/licenses/GPL-compatibility.html)을 적용했다. 배포 시의 GPL 조건은 [GPLv3 원문](https://spdx.org/licenses/GPL-3.0-only.html) 4–6절, Apache 조건은 [Apache-2.0 원문](https://www.apache.org/licenses/LICENSE-2.0) 4절을 기준으로 했다. MPL은 [Mozilla 원문](https://www.mozilla.org/en-US/MPL/2.0/) 3.1–3.4 및 [공식 FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/)를 기준으로 했다. 단순 네트워크 이용과 소스/바이너리 배포를 같은 상황으로 취급하지 않는다.

기술적 호환성만으로 두 안 중 하나가 강제되지는 않는다. 선택 기준은 downstream의 배포 의무를 어떻게 정할지다. GPL을 선택할 경우 최종 SPDX 표기는 `GPL-3.0-only`인지 `GPL-3.0-or-later`인지도 명시해야 한다. 이번 비교가 자동 dual-license 부여를 뜻하지 않는다.

## 실행한 dependency 검사

기존 `tools/ci/license_guard.py`와 허용 라이선스·예외 정책은 유지했다. 공개 범위에서 제외한 screenshot의 pending 항목만 제거했다.

- Core: 빈 Python 3.12 venv에서 통합 후보의 requirements와 pytest 설치 후 **46개 distribution PASS**. Runtime과 테스트 의존성을 합한 수다.
- Registry: 기존 격리 CI 환경 **11개 PASS**. 별도 `jsonschema==4.19.2` 환경이며 Core의 `jsonschema>=4.21,<5` 환경과 섞지 않았다.
- Screen 비교 환경: 기존 격리 CI 환경 **18개 PASS**. v0.1 기본 실행 범위로 채택했다는 뜻은 아니다.
- 합계는 중복 제거한 **49개 이름/버전 조합**이다. [전체 inventory](audit/dependency-license-inventory.json)에 scope와 양쪽 조건을 기록했다.
- 분류된 라이선스는 MIT, MIT-0, Apache-2.0, BSD-2-Clause, BSD-3-Clause, PSF-2.0, MPL-2.0, 0BSD, CC0-1.0, Zlib 계열이다. 이 메타데이터 범위에서 GPL/LGPL/AGPL distribution은 검출되지 않았다.
- Core의 라이선스 관련 파일 58개를 파일 해시로 비공개 보존했다. `primp==2.0.1` wheel에는 LICENSE 파일이 없어 정확한 upstream tag의 MIT LICENSE를 별도로 확보했다. 이것이 Rust wheel 안 모든 전이 라이브러리의 감사 완료를 뜻하지 않는다.
- 기존 license guard 회귀 검사 **8개 PASS**. 테스트를 삭제하거나 허용 라이선스를 늘려 통과시키지 않았다.

PASS는 distribution 메타데이터와 기존 정책의 결과다. wheel 내부 FFmpeg 등 별도 바이너리까지 승인한 것이 아니다. OpenCV/FFmpeg 번들, Windows/GPU/음성 엔진, npm 전이 의존성, Android SDK 및 모델별 약관은 별도 검토 전까지 v0.1 배포물에서 제외한다. GPL을 선택해도 LGPL/기타 고지·소스 의무가 사라지지 않는다.

## 공개 전 공통 차단 요인

1. **완료:** root license GPL-3.0-only 선택 및 LICENSE 추가. 외부 공개 최종 승인은 별도다.
2. 개인 configuration·경로·내부 주소·기기 식별자를 제거하는 공개 사본/이력 정제. 원본 private bundle은 별도 보존했다.
3. 출처 불명 asset/data와 재배포 미검증 바이너리의 export 제외 확인. 고지를 포함한 최종 파일 목록 검토.
4. 깨끗한 공개 후보 clone에서 기존 핵심 테스트·최소 데모·secret/license release gate 실행. **이번 감사는 그 전체 gate가 green이라는 보고가 아니다.**

새 production code: **0줄**. Core/Gate/Memory/Execution/Voice/Tool 구조 변경: **없음**. 외부 push·public 전환·release publish: **실행하지 않음**.
