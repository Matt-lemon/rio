# 리오의 개발 철학

**Rio is the system, not the LLM.**

리오는 모델을 바꿀 때마다 새로 시작하는 대화창이 아니라, 정체성·기억·작업의
연속성을 애플리케이션이 관리하는 로컬 어시스턴트를 지향한다. 이 문서는 Git에
남은 초기 README의 개발 원칙, 정체성/기억 분리 설계와 NAS 중심의 지속 실행
방향을 공개 가능한 형태로 정리하고, 재현 가능한 운영 원칙을 더한 것이다.
개인 설정이나 비공개 대화를 공개하는 문서는 아니다.

## 1. 모델은 교체할 수 있고, 리오의 연속성은 남는다

모델은 추론을 제공한다. 정체성 설정·성격·장기 기억·일시적 감정/상태·실행 기록은
서로 다른 개념이며 각 책임을 분리한다. 모델 교체를 기억 초기화나 권한 확대의
이유로 사용하지 않는다. 모델이 과거를 안다고 말하는 것과 실제 기억을 조회한
것도 구분한다.

## 2. 생활의 기반은 지속되고, 가속기는 필요에 따라 붙는다

초기 NAS 중심 설계의 핵심은 특정 장비나 모델명이 아니라 지속되는 기반이다.
음성·시각·고성능 추론은 독립 인터페이스로 연결한다. 한 기능의 장애 때문에
전체를 다시 만들거나 사용자의 다른 작업을 끊는 구성을 줄인다. 이것은 설계
목표이며 모든 배포에서 무중단 실행을 보장한다는 뜻은 아니다.

## 3. 제안과 권한은 다르다

모델의 계획, 웹 페이지, 도구 출력, 요약과 기억은 실행 권한을 만들지 못한다.
기존 도구를 먼저 찾고, 현재의 계약·대상·권한을 실행 직전에 검사한다.
새 도구 제작과 운영 변경은 사용자가 요청한 범위 안에서 진행한다.

## 4. 실제로 확인한 범위만 말한다

계획, 요청 전송, API 접수, 보고된 상태와 실제 작동은 같은 사건이 아니다.
결과가 불명확하면 기록을 남기고 같은 ID로 조회하며, 변경 명령을 무작정 다시
보내지 않는다. 이 구분을 일상적인 모든 동작마다 사용자에게 실물 확인을
요구하는 절차로 바꾸지 않는다. 정상 상태는 간결하게, 문제와 필요한 조치는
구체적으로 알린다.

## 5. 새로운 시도를 감당할 수 있는 운영을 만든다

동작하는 코드만 남기는 데서 끝내지 않는다. 소스·의존성·실행 방법과 검증 결과를
기록하고, 빈 환경에서 다시 만들 수 있는지 시험한다. Nix는 이 목표를 위한
선택적 도구다. 특정 패키지 관리자 사용을 리오의 정체성으로 삼지 않는다.

업데이트는 변경 확인 → 독립 검증 → 적용 → 상태 확인 순서로 진행한다.
돌아갈 버전을 준비하되, 코드 복귀와 기억·DB 복원은 별도로 판단한다.
과거 실패·미확정 명령을 지워서 정상처럼 보이게 만들지 않는다.

## 6. 사람의 생활을 기능보다 앞에 둔다

작게 바꾸고, 관련 검사로 확인하고, 이미 건강한 구성은 재사용한다.
자동 복구는 범위와 횟수를 제한한다. 테스트 성공을 실물 제어 성공으로,
연결 성공을 외부 서비스의 정상 동작으로 확대하지 않는다.

## 7. 공개 철학과 라이선스를 혼동하지 않는다

이 원칙은 프로젝트의 설계·리뷰 기준이다. 이용·수정·재배포에 추가 조건을 붙이는
라이선스 조항이 아니다. Rio의 직접 작성 부분은 기존 **GPL-3.0-only**를 유지하고,
외부 코드·의존성·모델·음성 자산의 원래 권리와 고지는 각각 보존한다.
설계 참고와 실제 코드 이식은 출처 문서에서 구분한다.

## 지금 구현된 범위

기존 Core의 도구 계약·영속 작업·요청 ID·fencing·UNKNOWN 처리와 오프라인 데모를
유지한다. 이번 추가는 공개 문서, 잠긴 최소 Nix 환경과 그 검증이다.
전체 NAS 재설치, 서비스 자동 전환, 운영 DB의 자동 복원, 모델/GPU/음성 환경의
완전 재현은 **아직 구현하지 않았다**.
